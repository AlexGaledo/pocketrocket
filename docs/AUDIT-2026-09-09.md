## B. Vulnerabilities

### Critical

1. **`Origin: null` bypasses the CSRF guard** — `api/guard.ts:32` `if (origin && origin !== 'null')`. `rest.ts:251` parses the body with no `Content-Type` check; `config.ts:68` defaults `HUB_TOKEN` to null. An `<iframe sandbox="allow-scripts">` on any site sends `Origin: null` + `text/plain` (no preflight) and reaches every mutating route. *Fix:* reject `'null'` like any foreign origin.
2. **`/screen/*` skips the bearer token** — `guard.ts:62` exempts every non-`/api/`, non-`/ws` path, but `hub.ts:121,159` proxy `/screen/` into noVNC with `ws: true`. Via #1 or any local process: `ws://127.0.0.1:7788/screen/websockify` → keyboard/mouse on a desktop that `deploy/pocketrocket-screen.service:7` runs as **root**. *Fix:* invert to an allowlist (`/`, `/assets/*`, `GET /api/health`, `/mcp`).
3. **Bash allowlist ignores relative paths** — `permissions/bashRules.ts:45-54` only matches *absolute* paths. `cat ../secrets.json`, `cd ../.. && cat secrets.json`, `echo x > ..\..\startup.bat` all return `allow` with no card — and `DATA_DIR` is the workspace's parent. *Fix:* resolve every path token (and post-`cd` cwd) against the roots.
4. **Allowlisted interpreters are unrestricted RCE** — `bashRules.ts:5-8` permits `node|python|bun|awk|sed|find|env|npx|npm run`. `node -e "..."`, `awk 'BEGIN{system(...)}'`, `find -exec sh -c`, `npm run <script-the-bot-just-wrote>` are auto-allowed. *Fix:* deny `-e`/`-c`/`--eval`/`-exec`/`run`; drop `env`/`awk`/`npx`.
5. **`isInside` accepts a path if *any* candidate is inside** — `pathRules.ts:28` ORs the resolved path with the realpath, and `real()` returns `null` for not-yet-existing files. A junction inside the workspace (creatable via #4) reads/writes anywhere. Verified empirically. *Fix:* require **all** candidates inside.
6. **Hub MCP tools are unconditionally allowed and escalate** — `PermissionBroker.ts:40` allows every `mcp__pocketrocket__*`. `agent/botTools.ts:266-304` lets a `Read`-only bot grant itself `["Bash","Browser","Desktop"]`, and writes any bot's `description` into that bot's `CLAUDE.md` (`:297`) — persistent cross-bot prompt injection surviving restart. *Fix:* route bot CRUD through `promptUser`; forbid self-widening `tools`.
7. **Children inherit the hub's whole `process.env`** — `claude.ts:180`, `codex.ts:298`, `grok.ts:95`, `opencode/server.ts:157`. `env`/`printenv` is allowlisted, so one prompt injection yields `POCKETROCKET_TOKEN` (full `/api/*` authority) plus every provider key. *Fix:* per-provider env allowlist.

### High

8. **Root Chromium, sandbox off, CDP origin check off** — `deploy/screen.sh:59-63` `--no-sandbox --remote-debugging-port=9222 --remote-allow-origins='*'` as root. Any local process attaches to CDP and owns the logged-in profile.
9. **Passwordless VNC + X access control off** — `screen.sh:65` `x11vnc -nopw`, `screen.sh:45` `Xvfb -ac`. Local-only, but the second half of #2.
10. **`request_approval` grants nothing** — `PermissionBroker.ts:66-80`: the card shows bot-authored free text and returns `{allowed:boolean}`; no capability binds the approval to what actually runs. TOCTOU by design.
11. **Skill pipeline is bot-writable** — `SkillService.ts:107-113` junctions `botHome` into the shared `SKILLS_DIR` (writes through it pass #5), letting a bot rewrite a human-approved skill. Separately `rest.ts:184` → `SkillService.ts:40-46` `cpSync(force:true)` with unvalidated `name` = arbitrary directory overwrite (reachable via #1).
12. **OpenCode bridge misattributes tool calls** — `opencode/bridge.ts:39` falls back to the newest live turn when two share a pending tool name. Bot A acts, spends budget and edits bots **as bot B**.
13. **`Glob`/`Grep` patterns are never path-checked** — `pathRules.ts:34-43` reads only `file_path|path|directory|cwd`, defaulting to `'.'`. `Grep({pattern:"BEGIN.*PRIVATE KEY", glob:"../../../**/*"})` runs with no card; the Claude `PreToolUse` hook shares the blind spot.
14. **`delete_bot` confirmation is bot-supplied** (`botTools.ts:306-330`, recursive `rmSync`), and `desktopTools.ts:121` allowlists launching `xfce4-terminal`, which `desktop_type`/`desktop_key` then drive — RCE that never touches `bashRules`.

### Medium

15. Unbounded request body (`rest.ts:248-251`, `hub.ts:112`) and **no rate limiting anywhere** → memory DoS, unimpeded brute force.
16. `guard.ts:64` compares the token with `===`, not `timingSafeEqual`; with #15, walkable byte-by-byte.
17. `SecretsStore.ts:31` `{mode:0o600}` is ignored when the file already exists, and on Windows only sets the read-only attribute — `secrets.json` inherits `DATA_DIR`'s ACL.
18. `grok/cli.ts:73-90` copies `~/.grok/auth.json` into `DATA_DIR/grok-home/` with no explicit mode, never cleans up, one `..` from the bot's cwd (#3). Undocumented.
19. `grok/cli.ts:129-144` puts the full system prompt **and the bot's memory file** on the command line — readable via `/proc/*/cmdline` or WMI.
20. `lib.rs:344`+`:272-286`: `hubDir` from `%APPDATA%\...\config.json` spawns bare `node` against attacker-chosen paths — userland persistence.
21. CI: `ci.yml` has **no `permissions:` block**; no action is SHA-pinned, including `dtolnay/rust-toolchain@stable` (a mutable branch) and `tauri-apps/tauri-action@v0` in the `contents: write` release job.
22. Child stderr tails reach the room and DB (`opencode/server.ts:201`, `codex.ts:382`) — can carry the inline config's `Authorization: Bearer` line or an echoed key.
23. `scripts/fetch-node.mjs`: the SHA256 check **is** genuinely enforced (`:87-89`), but there is no signature check despite the "signed SHASUMS256.txt" comment (`:11`), and the version is unpinned (`:33-40`).
24. `deploy/setup-vps.sh:28` symlinks `/etc/cron.daily/` into the deploy tree (daily root exec of a bot-writable file); `:23` installs `playwright@latest` as root.

### Low

No CSP/`X-Frame-Options` on hub responses (`hub.ts:136`); markdown links replace the app window (`ChatPane.tsx:339`); Google Fonts from a CDN in a "never leaves localhost" app; WS token in the query string (`lib/ws.ts:10`); `lib.rs:328` falls back to `time^pid` if the CSPRNG fails; `open_external` via `cmd /c start`; no leading-`-` guard on `ssh_host`; `decodeURIComponent` outside the try (`rest.ts:245`); `SecretsPatchSchema` accepts arbitrary keys; no CSP/HSTS on the site.

- `npx vitest run` → **152/152 pass**, incl. the Origin/Host/token guard, MCP turn-token expiry, `SecretsStore` no-leak.
- **Static serving is traversal-proof.** `hub.ts:127` uses the raw WHATWG `pathname`, never `decodeURIComponent`; 11 payloads (`/../..`, `%2e%2e`, `..%2f`, `..%5C`, `%00`, `/C:/Windows/win.ini`, `..;/`) stay inside `WEB_DIST`.
- **DNS rebinding blocked.** `guard.ts:29` demands a loopback `Host` first (`curl -H "Host: evil.example"` → 403); `127.0.0.2`, `127.1`, `0.0.0.0`, `127.0.0.1.evil.com`, `LOCALHOST`, `localhost.` all fail **closed**. `hub.ts:150-156` applies both checks to the WS upgrade too. No CORS headers are emitted anywhere.
- **No telemetry** — every `fetch(` in the hub is loopback or a test.
- **No XSS path.** `grep -rn 'dangerouslySetInnerHTML|innerHTML|eval\(|new Function|rehype' packages/web/src` → **zero**; `rehype-raw` is not a dependency; react-markdown 9's default `urlTransform` blocks `javascript:`/`data:`; tool args/output render as text nodes.
- **Token handling.** CSPRNG (`getrandom::fill`, 128-bit); `auth.ts:16-19` moves it from the URL fragment to `sessionStorage` then `replaceState`s it away; never in the window title or `hub.log`; no `req.url` logging exists. Per-turn MCP tokens are `randomBytes(24)`, unregistered in a `finally` (`BotRunner.ts:198-202`), scoped to that turn's tools.
- **Config injection resisted** — Codex `-c` and the OpenCode config use `JSON.stringify`; the Grok TOML is static with the token via `${ENV}`; the Codex prompt goes over stdin. One `shell: true` (`opencode/server.ts:169`), all its args hub constants.
- SQL fully parameterized (`db/db.ts:25-32`); `save_skill` name anchored; `read_room` fixed to `ctx.room.id`; memory `botHome`-scoped. Tauri capabilities are `core:default` on `main` only — no shell/fs/opener plugin, no remote IPC, no `devUrl`.
- **CI:** no `pull_request_target`, no `${{ github.event.* }}` in any `run:`, `release.yml:17` scoped to `contents: write`, publish gated on a tag matching `package.json`; `build-hub.mjs` ships no source maps or dev deps.
- **Repo/site:** repo `private`, `gh secret list` **empty**, default workflow permissions `read`; site returns HSTS/nosniff/DENY; `/main.js.map`, `/assets/`, `/.vercel/project.json` all 404. `.gitignore` covers `data/`, `*.log`, `.vercel`, `binaries/`, `build/`, `gen/`, `.claude/` (`git check-ignore -v`); local `data/` holds three real SQLite DBs, none ever tracked.

## D. Actions before public release, in order

1. **Redact the screenshots** (`app.png`, `app-dark.png`, `desktop-connection.png`, `settings.png`) and redeploy — this is public *right now*.
2. **Fix `guard.ts:32` and `:62`** (reject `Origin: null`; require the token for `/screen/*`). Two lines; closes the worst chain.
3. **Always generate a hub token** — drop the `HUB_TOKEN = null` default so local mode isn't unauthenticated.
4. **Rework `bashRules`/`pathRules`** (relative paths, interpreter flags, `isInside` AND-not-OR, `Glob`/`Grep` patterns) — or say plainly in SECURITY.md that the sandbox is best-effort against a cooperative model and no defence against a prompt-injected one.
5. **Gate bot CRUD behind human approval**; stop auto-allowing every `mcp__pocketrocket__*` tool.
6. **Stop spreading `process.env`** into provider children.
7. **Server mode:** drop `--remote-allow-origins='*'`, run the screen unit non-root, password x11vnc, drop `Xvfb -ac`, copy instead of symlink into `/etc/cron.daily`, pin `playwright`.
8. **Redact remaining path/host strings** (`.env.example`, `PLAN.md`, `PRODUCTION-CHECKLIST.md`, fixtures, `events.test.ts`); widen `.gitignore` to `.env*`, `secrets.json`, `auth.json`.
9. **GitHub before flipping public:** enable secret scanning + push protection (disabled today) and Dependabot alerts, protect `main`, add `permissions: contents: read` to `ci.yml`, SHA-pin every action.
10. Then: body-size caps, rate limiting, `timingSafeEqual`, `chmodSync` after each `secrets.json` write, security headers. A `git filter-repo` pass would clear `crm-agency` and the old image blobs — cosmetic only, since no credential ever entered the repo.
