# P9: Phone, devices, more desktops

User-visible changes, for the integrator to merge into `CHANGELOG.md` `[Unreleased]`.

## Added
- **Pair a phone** (Settings › Devices). The desktop shows a QR code holding the hub's URL and a one-time
  8-character code that expires after 5 minutes. It never holds the hub token. The phone trades the code for a
  device token of its own. The device list shows when each device was paired and last seen, and you can
  revoke one. A revoked phone is refused on its next request, and its open connection and Screen are closed
  at once. A phone can also unpair itself.
- **What a phone can do:** read bots, rooms and messages, chat, answer approval cards (once only; "always"
  stays a desktop decision), watch a Screen, and create, edit and run Automations. Settings, approvals, API
  keys, integrations, the account, bot and room edits, and pairing more devices answer 403 from a phone.
- **Installable web app (PWA):** a manifest, icons, and a service worker that caches only the app shell, never
  messages or API answers. The phone layout gets safe-area padding, 16px inputs (no iOS zoom), full-width
  drawers and 44px approval buttons.
- **Notifications (opt-in, per device):** Web Push with a VAPID key minted on the hub's machine. A push says
  only "A bot needs your approval", "Routine finished" or a test line. The encrypted payload is
  `{"kind":…}`, with no bot, room or message text. Bursts are coalesced to one push per kind every 30 seconds.
- **Phone access over Tailscale Serve** (docs/SERVER.md), off by default. `POCKETROCKET_ALLOWED_HOSTS=<machine>.<tailnet>.ts.net`
  lets the hub answer to that name, but only on HTTPS requests forwarded from loopback. Never Funnel.
- **Tray icon and close-to-tray** in the desktop app. In local mode, closing the window keeps the hub and bots
  running. Show and Quit are in the tray, and "Keep running when window closes" is in the tray and on the
  connection page. Quit really quits and still stops every child process.
- **Linux (AppImage, deb) and macOS (unsigned dmg) builds** in the release workflow, with `cargo check` for
  both in CI.

## Internal
- Migrations 90–91: `devices(id, name, token_hash, created_at, last_seen_at, revoked)` and
  `push_subscriptions(id, device_id, endpoint, p256dh, auth, created_at)`. Only the SHA-256 of a device
  token is stored, and it is compared in constant time.
- `api/guard.ts`:
  - `checkRequestOrigin(req, port, { allowedHosts })` and `forwardedHttps()`.
  - The `deviceToken` hook in `checkToken`, with `POST /api/devices/pair` as a token-exempt route (each miss
    feeds the rate limiter).
  - `Principal` / `principalOf` / `deviceIdOf`.
  - **`deviceMayAccess`, the device allowlist:** a route that is not listed is refused for devices.
- New routes: `/api/devices`, `/api/devices/pairing` (hub token only), `/api/devices/:id` (PATCH: hub only;
  DELETE: hub, or the device itself), and `/api/push`, `/api/push/{subscribe,unsubscribe,test}`. A push
  endpoint must be a browser push service (FCM, Mozilla, Apple, WNS).
- `ScreenSessions` tickets and sessions carry the device that minted them (`ownerOf`, `revokeOwner`).
- The hub serves `sw.js` and `manifest.json` uncached.
- New environment variables: `POCKETROCKET_ALLOWED_HOSTS` and `POCKETROCKET_PUSH_SUBJECT`. The VAPID key is
  stored in `<data>/vapid.json` (0600).
- Desktop:
  - `closeToTray` in `config.json`.
  - On Unix the hub runs in its own process group.
  - `fetch-node.mjs` fetches the Node sidecar for each platform (`binaries/node-<triple>`, or set
    `NODE_SIDECAR_TARGET`).
