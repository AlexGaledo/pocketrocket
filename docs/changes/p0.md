# P0: Fork and foundations

User-visible changes (already merged into `CHANGELOG.md` `[Unreleased]`; P0 is the one phase that edits it directly).

## Changed
- **Name and side-by-side install.** The app is PocketRocket Crew. It has its own Tauri id
  `com.pocketrocket.crew` (own `%APPDATA%\com.pocketrocket.crew` folder, own single-instance lock), exe
  `PocketRocketCrew.exe`, default hub port **7790**, and browser storage keys `prcrew.*` (a fresh app, so
  nothing is carried over from `pocketrocket.*`). The desktop app no longer copies data from an old
  Claudebot install.
- **Server.** `scripts/deploy.sh` and `deploy/setup-vps.sh` install as user `pocketrocket-crew` into
  `/home/pocketrocket-crew/pocketrocket-crew`, with units `pocketrocket-crew.service` and
  `pocketrocket-crew-screen.service`, cron jobs `pocketrocket-crew-*`, backups in
  `/var/backups/pocketrocket-crew`. The screen uses display `:98`, CDP 9223, VNC 5901 and noVNC 6081
  (`deploy/screen.sh` now reads `SCREEN_DISPLAY`/`CDP_PORT`/`VNC_PORT`/`NOVNC_PORT`), so a stock
  PocketRocket can run on the same VPS. The upstream "claudebot → pocketrocket" and "root → service user"
  migrations were removed from `deploy.sh` so a Crew deploy never moves a stock install. The desktop
  server scan looks only for Crew installs.
- **Releases** are built only in, and published to, `AlexGaledo/pocketrocket-crew`.
- **Cost cap on every cause.** The per-thread cap (`CAUSE_COST_CAP_USD`, $5) now bounds user-started and
  routine turns too (and future trigger turns, which go through the same lanes): each turn's budget is
  min(bot budget, what is left of the cap), and a queued turn whose thread is already over the cap does
  not start; a system note says so and a routine run is recorded as an error.
- **Room size over REST** is `MAX_ROOM_BOTS` (10), was 6.

## Fixed
- Approval cards still pending when the hub stopped are marked **expired** on the next start and read
  "Expired — the hub restarted. Ask the bot to retry." (new `ApprovalPayload.status` value `expired`).
- `PATCH /api/rooms/:id` enforces "a DM has exactly one bot" and checks that new members exist.
- `DELETE /api/bots/:id` deletes `data/bots/<id>` (shared `MemoryService.removeHome`, also used by `delete_bot`).
- The user avatar initial and the Chief-of-staff preset use `settings.userName` instead of "A"/"Alex".
- Pending skills in the Skills tab show their amber border (`border-warn/40` had no border width).

## Not user-visible
- Versioned migrations: `schema_version` table and `registerMigrations` in `packages/hub/src/db/migrations.ts`
  (documented at the top of `db.ts`). The three old ad-hoc column checks are versions 1–3.
