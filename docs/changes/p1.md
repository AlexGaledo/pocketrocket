# P1: Per-bot computers

User-visible changes for the `[Unreleased]` section of `CHANGELOG.md` (the integrator merges them in).

## Added
- **Each bot gets its own computer on a server hub.** A bot with the Browser or Desktop tool now has its own
  virtual display, XFCE desktop, Chromium profile (its own logins) and disk, instead of every bot sharing
  one screen. Its desktop links the shared workspace as `~/Shared`. Bots are told about "your computer" in
  their prompt. These computers are separate, **not isolated**: every bot runs as the same OS user, so a bot
  with shell access can still read another bot's files and logins. The UI and docs say so.
- **Computers sleep and wake on their own.** A computer starts the first time its bot uses Browser or
  Desktop, and stops after `COMPUTER_IDLE_MIN` (30) minutes with no tool use, nobody watching, no routine
  due and Keep awake off. Its disk is kept. At most `MAX_RUNNING_COMPUTERS` (3) run at once; the least
  recently used idle one makes room, and if all are busy the bot runs that turn without Browser/Desktop and
  says why.
- **Soft disk quota** per computer (`COMPUTER_QUOTA_GB`, 10): the bot is warned at 80%, and at 100% the
  computer does not start until space is freed.
- **Screen tab follows the bot** selected in the right panel and shows its computer: Asleep, Starting or
  Live, a **Wake** button, a **Keep awake** switch and a disk badge (amber at 80%, red at 100%).
- New REST routes: `GET /api/screen?botId=`, `GET /api/computers/:botId`,
  `POST /api/computers/:botId/wake`, `PUT /api/computers/:botId/keep-awake`. New WS event
  `computer.state`.
- **Restic option for backups** (off by default): set `RESTIC_REPOSITORY` and `RESTIC_PASSWORD_FILE` in
  `/etc/default/pocketrocket-crew-backup` for incremental snapshots on the VPS.

## Changed
- **Server setup.** `deploy/setup-vps.sh` installs the systemd user unit
  `pocketrocket-crew-computer@.service` (`deploy/computer.sh`), enables lingering for `pocketrocket-crew`,
  turns per-bot computers on in a hub drop-in, and stops the shared screen unit.
  `POCKETROCKET_COMPUTERS=0 bash deploy/setup-vps.sh` keeps the one shared screen. The hub unit no longer
  pulls the shared screen in.
- **Ports.** Computer slot `n` uses display `:200+n`, CDP `9400+n`, VNC `5800+n` and noVNC `6200+n`, all on
  127.0.0.1, clear of the shared Crew screen and of stock PocketRocket.
- **Existing logins move to the first Browser bot.** On the first start with per-bot computers on, the hub
  moves `data/browser-profile` and `data/desktop-home` to the oldest bot with the Browser tool (once the
  shared screen is stopped).
- **Screen tickets are per bot.** A ticket for one bot's screen opens that screen only
  (`pr_screen_<botId>`, `Path=/screen/<botId>`); it is refused on any other bot's screen and on the shared
  screen.
- A bot's own computer disk (`data/computers/<id>/files`, where its downloads land) is one of the folders
  its file tools may use without an approval card.
- Deleting a bot also stops its computer and erases `data/computers/<id>`.
- Backups skip each computer's browser and desktop caches. `docs/SERVER.md` has a RAM sizing table.

## Unchanged
- The desktop app (Windows/local hub) and any server with per-bot computers off behave exactly as before:
  one shared screen, shared profile, same Screen tab.
