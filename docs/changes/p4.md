# P4: Integrations

Release notes for the integrator to merge into `CHANGELOG.md` under `## [Unreleased]`.

### Added
- **Settings → Integrations.** Connect GitHub, Google (Gmail, Calendar, Drive), Slack, ClickUp and Microsoft
  Teams. Each provider offers **Connect with OAuth** (your own OAuth app: client id, and secret or tenant, with
  PKCE and a loopback redirect `/oauth/callback/<provider>`; GitHub and Teams also offer a device code for a hub
  on a server) and/or **Paste a token** (GitHub PAT, Slack `xoxb-` + optional `xapp-`, ClickUp `pk_`). Defaults:
  Google and Teams OAuth, Slack and ClickUp paste, GitHub both. Each card has short setup steps with links, a
  masked account name, status, Test connection, Reconnect and Disconnect.
- **Per-bot access.** Connections are shared, but a bot gets a provider's tools only after it is switched on
  under that connection. A bot without access does not see the tools at all.
- **Bot tools.** GitHub: search/list/read issues and PRs, notifications, create issue, comment. Google: Gmail
  search/read/send, Calendar list/create, Drive search/read. Slack: list channels, read history, post. ClickUp:
  list lists, list/search/read tasks, create task, comment. Teams: list chats, read chat, send chat message.
  Reads run without asking and are labelled as untrusted third-party content. **Every write shows an approval
  card on every call, also when approvals are bypassed**, and an "Always" answer is not remembered.
- **Poll-friendly client API** for P5 triggers (GitHub If-Modified-Since/ETag, Gmail historyId, Calendar
  syncToken, Drive changes, Slack Socket Mode URL, ClickUp `date_updated_gt`, Teams chats), documented in
  `docs/specs/integrations-client-api.md`.

### Security
- Integration credentials are stored AES-256-GCM encrypted in `data/integrations.json`; the key is
  `data/vault.key` (owner-only, created on first connect). A tampered file is refused rather than reset.
- `deploy/backup.sh` leaves `vault.key` out of archives, so a backup alone holds no usable token. Back the key
  up separately (`docs/SERVER.md`, `docs/CONFIGURATION.md` §7).
- Tokens never reach a bot: tools run in the hub, tokens are not in any env, prompt or tool output, and every
  stored value plus the GitHub/Slack/ClickUp/Google/Microsoft token shapes are added to redaction.
- `/oauth/callback/<provider>` is token-exempt like `/auth/callback`, but accepted only for a state this hub
  minted (single use, 10 minutes, same provider) and counts as a failed auth for the rate limiter otherwise.
- New outbound hosts, only after the user connects a provider; listed in `docs/PRODUCTION-CHECKLIST.md`.

### Internal
- Migration 40: `integrations` and `bot_integrations` tables. `HubOptions.integrations` takes a factory
  `(db) => IntegrationService` for tests. `db.test.ts` now derives the expected version list from the registry
  so later phases' blocks do not break it.

### Not verified
- No real OAuth round trip was run against any provider; all tests use HTTP mocks. In particular: ClickUp's
  acceptance of a loopback redirect and its token endpoint's form encoding, and Microsoft's device flow
  against a single-tenant app.
- Windows DPAPI wrapping of `vault.key` is not implemented; the file's owner-only ACL is the control there.
