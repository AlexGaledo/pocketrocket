# P5: Event triggers

User-visible changes, for the integrator to merge into `CHANGELOG.md` `[Unreleased]`.

## Added
- **Triggers.** A trigger wakes a bot in a room when something happens in a connected integration:
  GitHub notifications, GitHub repository events, Gmail, Google Calendar, Google Drive, Slack, ClickUp and
  Microsoft Teams. Events arrive by outbound polling (GitHub with `If-Modified-Since`/ETag and its
  `X-Poll-Interval`, Gmail history, Calendar sync tokens, Drive changes, ClickUp `date_updated_gt`, Teams chats)
  and, for Slack, over **Socket Mode** (an outbound WebSocket; needs the `xapp-` app token). The hub still opens
  no inbound port and uses no relay (decision Q5).
- **Automations tab.** The Routines tab is now **Automations**, with two sections: **Schedules** (the existing
  routines) and **Triggers**. The trigger builder offers only connected sources, a filter per source (repository,
  event, action, label, actor; from, subject, label; calendar, title, status; channel, user, text; workspace,
  list, status, assignee; chat, from, text), the bot and room, a prompt with `{{event.*}}` placeholders (click to
  insert), a per-hour limit and a per-day budget, and an enabled switch. Each trigger shows fires this hour, spend
  today, when its source was last checked or why it failed, a **Send a sample event** button, and its recent
  fires with status, cost and the reason a fire was skipped. It warns when the chosen bot has no access to the
  connection.
- **Trigger messages** show in the chat as a "Trigger: name" line; the outside event is folded under
  "Event (untrusted)" and shown as plain text.

## Security
- **Event text is untrusted data.** The whole event goes into the turn inside a block fenced by markers that carry
  a random nonce, with a note that it is content from an external sender and not instructions. Fence-like text
  and control/bidi characters inside the event are defused. `{{event.*}}` placeholders in the prompt are filled
  with a quoted, single-line copy of the value, capped at 300 characters.
- **Trigger turns always ask** (decision Q6): a trigger-fired turn, and every bot hop it causes, goes through
  approval cards even when approvals are bypassed. Tested with an injected GitHub comment that tells the bot to
  run `curl … | sh` with Bash: under bypass it still raises a card, and a deny stops it.
- **Limits.** Each trigger has a rolling hourly fire limit (default 6) and a rolling 24-hour budget (default
  $2), counted from `usage` by cause, so the hops a trigger turn causes count too. The turn's budget is capped at
  what is left of it; the thread cost cap still applies. Over a limit, the fire is recorded as skipped with the
  reason.
- **Access.** A source is polled only while an enabled trigger's bot holds a grant for a connected provider (not
  expired). A real event is skipped if the bot lost its grant since. A stream whose credential is refused stops
  until the connection is fixed. Bots cannot create, change or enable triggers (REST only, hub token).
- Mail the account sent (`SENT`/`DRAFT`), Slack bot posts and edits, and Teams messages from the signed-in user
  do not fire triggers, so a bot replying does not trigger itself.

## Changed
- REST: `GET/POST /api/triggers`, `PATCH/DELETE /api/triggers/:id`, `GET /api/triggers/:id/fires`,
  `POST /api/triggers/:id/test` (optional `{ event: { title, text, from, url, fields } }`).
- WS: `triggers.changed` (refetch `GET /api/triggers`) and `trigger.fired { triggerId, fireId, status }`.
- Messages: new kind `trigger` with a `TriggerPayload`; bots see it as conversation (`[trigger]`) and in
  `read_room`.

## Not user-visible
- Migrations 50–53 (P5 block `[50, 59]`): `triggers`, `events_inbox` (UNIQUE `dedupe_key`, status
  `new`/`matched`/`ignored`), `trigger_fires`, `trigger_cursors` (per stream: cursor, ETag, last/next poll,
  failures, last error).
- `services/TriggerService.ts` (pollers, matcher, limits), `services/SlackSocketMode.ts` (acks every envelope
  before handling it, reconnects on `disconnect` at once and on a dropped socket with 1 s…60 s backoff, stops on a
  refused or missing app token), `db/triggerRepo.ts`, `rooms/untrusted.ts`, `api/triggers.ts`.
- `RoomRouter.fireTrigger()` (kind `trigger`, `causeKind: 'trigger'`, per-item `budgetUsd`); strict approvals come
  from the existing `requiresApprovals(causeId)` because the cause is a system message.
- Polls: 60 s default (Calendar 120 s, Drive 300 s), the provider's own minimum wins; a failing stream backs off
  doubling up to 30 minutes. The first poll of a stream only seeds its cursor, so turning a trigger on never
  fires on history. Gmail/Calendar cursor expiry (404/410) re-seeds and notes that the gap was skipped.
- Restart: cursors and the inbox are in SQLite. Events stored but not yet matched are matched on start; fires
  left `running` are closed as errors ("The hub restarted during this turn"). Handled inbox rows are pruned after
  14 days.
- `@pocketrocket/shared` `triggers.ts`: sources, filter fields, `TriggerInputSchema`, `TriggerPatchSchema`.

## Known limits
- Slack does not replay events sent while the socket was down; there is no `conversations.history` catch-up yet.
- The per-trigger budget is not journaled with the lane item, so a trigger turn resumed after a restart is
  capped only by the thread cost cap.
- Teams covers 1:1 and group chats (delegated `/me/chats`), not channel messages. A chat with several new
  messages between polls fires once, on the latest preview.
- Not verified against real providers: all polling is tested with recorded fixtures over `fakeFetch` and a fake
  socket. In particular Slack Socket Mode against a live app, GitHub's `X-Poll-Interval` on `/repos/*/events`, and
  ClickUp `date_updated_gt` paging over 100 tasks.
