# P8: Model router and usage

User-visible changes, for the integrator to merge into `CHANGELOG.md` `[Unreleased]`.

## Added
- **Auto model.** A bot's model can be **Auto** (BotDialog, and the default model in Settings). The hub then
  picks the model per turn (`agent/ModelRouter.ts`), always from the active provider's own list:
  - auto-memory and skill-reflection passes → Haiku;
  - an explicit ask in the new messages ("think hard", "ultrathink", `/opus`) or a `/skill-name` / "the
    skill-name skill" for an assigned, approved skill whose `SKILL.md` frontmatter says `model: opus` → Opus;
  - routine and trigger turns ("anything to do?" triage) → Haiku;
  - everything else → Sonnet 5;
  - a turn that hits the step limit continues on Opus ("… continuing (1/2) on claude-opus-5 (escalated by the
    model router)").

  On Codex/Grok/OpenCode the tiers map to that provider's cheapest / default / hardest-tasks model; a tier it
  does not have falls back to its default. Switching provider leaves Auto bots on Auto. The router never
  touches a bot's budget: escalation spends what is left of the same `max_budget_usd`.
- **Model chip** on every bot turn in the chat: the model that wrote it, with the router's reason in the
  tooltip (e.g. "Auto: Haiku to triage a routine"). Pinned bots show their model and "Set on the bot".
- **Usage by model and by what started it** in the Usage tab: your messages, bot hand-offs, routines,
  triggers, auto-memory. Spend recorded before this release is backfilled where the data allows, otherwise
  listed as "Not recorded". `GET /api/usage` also returns `byModel` and `byCause`.
- **Smarter Auto routing** (Settings › Claude, off by default): a one-shot Haiku classifier, capped at
  $0.002 a turn, picks the tier when no rule above applies. Its cost is recorded against the turn's thread.
  Claude only.

## Internal
- Migrations 80–84: `usage.model`, `usage.route_reason`, `usage.cause_kind` (with backfill),
  `messages.model`, `messages.model_reason`.
- `TurnRequest.causeKind` (`user` | `bot` | `routine` | `trigger` | `memory` | `reflection`);
  `RoomRouter.fireRoutine(…, causeKind = 'routine')`. `TurnResult` gains `model` and `modelReason`.
- `db.test.ts` no longer assumes only P0 migrations are registered.
