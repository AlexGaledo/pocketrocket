# P7: Memory, voice, knowledge repo

User-visible changes for `CHANGELOG.md` `[Unreleased]` (the integrator merges them in).

## Added
- **Knowledge repo (Settings › Knowledge).** `settings.knowledgeRepo` takes a git URL (`https://`, `ssh://`,
  `git://`, `file://`, `git@host:path`) or an absolute folder on the hub's computer. A URL is shallow-cloned
  to `<data>/knowledge` and refreshed with `git pull --ff-only` at start, on a Settings change, every
  `KNOWLEDGE_SYNC_MINUTES` (default 60) and on **Sync now**. A folder is linked there (a junction on
  Windows), so edits show up at once. The section shows the state (cloned / linked / syncing / failed), the
  commit, the last sync time and the last error. A failed pull keeps the last good clone readable.
- **Every bot reads it; none can write it.** The folder is added to each Claude bot's
  `additionalDirectories` and named in the prompt ("read-only, cite the file path"). Read, Glob, Grep and the
  plain shell readers (`cat`, `head`, `tail`, `grep`, `rg`, `ls`, `wc`, also after `cd` into it) need no
  card. Every write — Write, Edit, MultiEdit, NotebookEdit, a shell redirect, `cp`/`mv`/`rm`, `sort -o`,
  `uniq in out`, `tree -o` — raises an approval card. A PreToolUse hook stops `acceptEdits` from
  auto-accepting writes there, and under approvals **bypass** the hook denies them outright.
- **Notes (per bot).** `bots/<id>/notes/*.md`, written with the new hub tool `write_note` (title becomes a
  kebab-case file name; 32 KB per note, 500 notes) and searched with `search_notes` (every term must match;
  returns paths and matching lines). Notes never enter the prompt; `memory.md` stays 8 KB.
- **Voice (per bot).** `bots/<id>/voice.md`, up to 1 KB of style notes, included in every prompt under
  "## Voice" and editable in the Memory tab. Auto-memory may now *propose* voice notes when you corrected a
  bot's wording; they wait under "Proposed from your edits" until you approve (appended to voice.md) or
  dismiss them. Proposals are cleaned like memory notes (no secrets, one line) and capped at 10 per bot.
- **Fleet directory.** The prompt lists the bots that are not in the room (handle, title, first line of the
  description), capped at 25 bots, 110 characters per line and 2.4 KB in total, with "+N more: call
  list_bots" past that. `handoff` to one of them in a group chat adds it to the room through the
  `add_to_room` approval card first, then hands over the task. In a DM it says the bot cannot join.
- **Import skills from git (Skills › From git).** `POST /api/skills/import-git { url }` shallow-clones a URL
  into a temp folder (always removed) or scans a local folder in place, and copies every folder with a
  `SKILL.md` (up to 4 levels deep, e.g. `skills/<n>` or `plugins/<p>/skills/<n>`) into the pool as
  **imported + pending**. Skipped, with the reason shown: names already in the pool (never overwritten),
  invalid names, no `description`, `SKILL.md` over 64 KB, folders over 1 MB / 200 files, folders containing
  a symbolic link. At most 50 per import. Pending imported skills now show the amber **review** badge.
- REST: `GET /api/knowledge`, `POST /api/knowledge/sync`, `GET|PUT /api/bots/:id/voice`,
  `POST /api/bots/:id/voice/proposals/:pid { decision: approve|dismiss }`, `GET /api/bots/:id/notes`,
  `POST /api/skills/import-git`. WS events `knowledge.status` and `voice.updated`.
- DB migrations 70 (`knowledge_sync`) and 71 (`voice_proposals`).

## Security notes
- Git runs through `execFile` with an argument array; the source comes after `--`. Sources starting with
  `-`, `ext::`/`fd::` and other `<helper>::` transports, control characters, relative paths and UNC paths
  are refused, and every call sets `protocol.ext.allow=never`, `protocol.fd.allow=never` and an empty hooks
  path. `GIT_TERMINAL_PROMPT=0` and ssh `BatchMode` keep a private repo from hanging on a prompt. The child
  env is an allowlist (never `POCKETROCKET_TOKEN`).
- A local knowledge folder that contains, or sits inside, the hub data folder is refused, so linking can never
  expose `secrets.json` or the hub token to every bot.
- Only the human (REST) changes the knowledge source, syncs it, or approves voice notes; no bot tool can.

## Known limits
- Under approvals **bypass**, only the Claude file tools are blocked from writing the knowledge folder; a
  shell command could still write there (bypass allows every shell command by design).
- Codex / OpenCode / Grok (dev-only) are told about the folder but do not get it added to their sandbox.
- The knowledge pull is a hub timer, not a row in the Routines list.
